Inside MockInstaller

MockInstaller owns dynamic WireMock state for one scenario. It installs scoped mappings, counts scoped calls, and removes scoped state. This page follows the class from top to bottom. It explains each function, each cleanup branch, and each Kotlin feature in Java terms.

1Why it exists

Journeys share four WireMock instances. Each scenario needs isolated state. MockInstaller applies one test-ID matcher to every installed mapping. It uses the same matcher to count calls and remove state.

This ownership rule is more important than the mapping shape. A failed service can send a request that no stub matches. The request journal can still contain that call. Cleanup must also remove unused mappings. The test ID connects both types of state to the scenario.

scenariotestId = testIdFor(featureName, scenarioName)
installmapping request header ← exact test-ID matcher
countone target journal ← ANY method + .* URL + same matcher
cleanupall target mappings and journal events ← same matcher

Core invariant: installation and recovery use the same ownership marker.

2How to use it

Journey authors do not construct this class. ScenarioScope creates one installer. Its helper methods supply the scenario test ID. Authors call the short forms below.

testkit/JourneySpec.kt 
installFor(booking)
installFor(booking, excluded = setOf(stubId))
installStub(customStub)   // override: excluded default's ID above, own ID here

expect("AEM was not called") {
    callCount(Upstream.AEM) shouldBeExactly 0
}
// Java would usually expose a scenario facade with the test ID as state.
scenario.installFor(booking);
scenario.installFor(booking, Set.of(stubId));
scenario.installStub(customStub);

assertEquals(0, scenario.callCount(Upstream.AEM));
OperationPurposeTarget scope
installForSelect and install the Booking plan.Each planned stub chooses its target.
installStubInstall one direct planned stub.The planned stub chooses its target.
callCountCount all calls owned by this scenario.One requested upstream.
removeForRemove owned mappings and journal events.Every WireMockTarget.

The lifecycle calls removeFor after the scenario. Provisioning also calls it when a client deletes a mock session. Both paths use the same recovery operation.

4Implementation walkthrough

installFor

installFor asks selectedStubs for the legal plan. An empty plan records evidence and performs no WireMock call: empty-plan evidence when the Booking selected nothing, fully-excluded-plan evidence when exclusions emptied a plan that did select stubs. A non-empty plan goes through installStub. This method overwrites any old ownership matcher before registration.

testkit/mocks/MockInstaller.kt 
suspend fun installFor(
    booking: Booking,
    testId: String,
    excluded: Set<String> = emptySet(),
) {
    val selected = selectedStubs(booking, excluded)

    if (selected.isEmpty()) {
        if (excluded.isEmpty()) {
            evidenceSink?.recordEmptyPlan("Booking", testId)
        } else {
            evidenceSink?.recordFullyExcludedPlan("Booking", excluded, testId)
        }
        return
    }

    for (stub in selected) {
        installStub(stub, testId)
    }
}
void installFor(Booking booking, String testId,
                Set<String> excluded) {
    List<PlannedStub> selected = selectedStubs(booking, excluded);
    if (selected.isEmpty()) {
        if (evidenceSink != null) {
            if (excluded.isEmpty()) {
                evidenceSink.recordEmptyPlan("Booking", testId);
            } else {
                evidenceSink.recordFullyExcludedPlan("Booking", excluded, testId);
            }
        }
        return;
    }
    for (PlannedStub stub : selected) installStub(stub, testId);
}

Selection happens before WireMock I/O. selectedStubs rejects excluded IDs the Booking did not select. Therefore an invalid plan installs nothing. The empty-plan branch is a successful no-op. It records why no mapping evidence exists.

installStub

testkit/mocks/MockInstaller.kt 
internal suspend fun installStub(
    stub: PlannedStub,
    testId: String,
) {
    val scoped = stub.scopedTo(testId)
    for (mapping in scoped.mappings) {
        wiremock[scoped.target].stub(mapping)
        evidenceSink?.recordInstalledStub(scoped.id, mapping, testId)
    }
}
void installStub(PlannedStub stub, String testId) {
    PlannedStub scoped = ScopedStubs.scopedTo(stub, testId);
    for (StubMapping mapping : scoped.mappings()) {
        wiremock.get(scoped.target()).stub(mapping);
        if (evidenceSink != null) {
            evidenceSink.recordInstalledStub(scoped.id(), mapping, testId);
        }
    }
}

Evidence comes after a successful Admin call. A failed registration does not create success evidence. Earlier mappings can still exist after a later failure. Cleanup can find them by their ownership matcher.

countCallsFor

countCallsFor queries one request journal. The query accepts every method and URL. It only restricts the target and test ID. This broad shape catches calls that match no installed stub. It makes an absence assertion useful.

testkit/mocks/MockInstaller.kt 
suspend fun countCallsFor(
    target: WireMockTarget,
    testId: String,
): Int = wiremock[target].countRequests(anyScopedRequest(testId))
int countCallsFor(WireMockTarget target, String testId) {
    return wiremock.get(target).countRequests(anyScopedRequest(testId));
}

The expression body returns the Admin count directly. It performs one request against one target. It does not require prior stub installation. The WireMock adapter rejects a disabled request journal. This prevents a false zero result.

anyScopedRequest

This private method creates the request pattern used by countCallsFor. It accepts every HTTP method and every URL. It then restricts the query with the exact test-ID baggage matcher. The method returns data only. It performs no I/O.

testkit/mocks/MockInstaller.kt 
private fun anyScopedRequest(testId: String): RequestPattern =
    RequestPattern(
        method = "ANY",
        urlPattern = ".*",
        headers = mapOf(BAGGAGE_HEADER to testIdHeaderMatcher(testId)),
    )
private RequestPattern anyScopedRequest(String testId) {
    return new RequestPattern(
        "ANY",
        ".*",
        Map.of(BAGGAGE_HEADER, testIdHeaderMatcher(testId))
    );
}

Cleanup overview

Cleanup visits every enum target in order. It lists mappings first. It selects mappings with the exact test-ID matcher. It then deletes each selected mapping by its WireMock ID. Journal cleanup runs even when listing or deletion fails.

for targetWireMockTarget.entries
listGET /__admin/mappings → select exact owner
deleteDELETE /__admin/mappings/{id} for each owned mapping
journalPOST /__admin/requests/remove with exact owner criteria
resultcounts + all failures → CleanupResult.orThrow()

removeFor

removeFor is the public entry point. It changes only the coroutine context. The private method owns the cleanup algorithm. This split keeps the cancellation policy at the boundary.

testkit/mocks/MockInstaller.kt 
suspend fun removeFor(testId: String): CleanupResult =
    withContext(NonCancellable) {
        removeScopedStateFor(testId)
    }
// Java has no direct NonCancellable equivalent.
CleanupResult removeFor(String testId) {
    return cleanupScope.run(() -> removeScopedStateFor(testId));
}

removeScopedStateFor

removeScopedStateFor owns steps 2 through 7. It attempts every reachable operation. It returns one aggregate result after the target loop finishes.

private suspend fun removeScopedStateFor(testId: String): CleanupResult is private because callers must enter through the NonCancellable removeFor boundary.

2. Create one aggregate result

The private method creates counters and a failure list for one attempt. Its local helper adds the target name, URL, operation, optional mapping ID, and original cause. This structure keeps enough data for reports and stack traces.

val failures = mutableListOf<CleanupFailure>()
var removedMappings = 0

    failures += CleanupFailure(
        wireMockName = target.displayName,

}

3. Build one exact journal criterion

Cleanup builds the request-journal criterion once. The URL pattern accepts all paths. The baggage matcher limits ownership to the exact test ID. Every target receives the same criterion.

4. List mappings without stopping recovery

The loop resolves one Admin adapter for each enum target. A successful list produces a list. A cancellation propagates. Another exception records LIST_MAPPINGS and produces null. Null means that mapping deletion is not reachable for this target.

testkit/mocks/MockInstaller.kt 
for (target in WireMockTarget.entries) {
    val admin = wiremock[target]
    val stubs =
        try {
            admin.listStubs()
        } catch (failure: CancellationException) {
            throw failure
        } catch (failure: Exception) {
            recordFailure(
                target = target,
                admin = admin,
                operation = CleanupOperation.LIST_MAPPINGS,
                cause = failure,
            )
            null
        }
    // deletion and journal cleanup continue below
}
for (WireMockTarget target : WireMockTarget.values()) {
    WireMockAdmin admin = wiremock.get(target);
    List<StubMapping> stubs;
    try {
        stubs = admin.listStubs();
    } catch (CancellationException failure) {
        throw failure;
    } catch (Exception failure) {
        recordFailure(target, admin, LIST_MAPPINGS, failure, null);
        stubs = null;
    }
}

The catch block is an expression branch. Its final null becomes the value of stubs. Kotlin infers List<StubMapping>? for the variable.

5. Select and delete owned mappings

A non-null list permits deletion. The filter reads the baggage header matcher from each mapping. Missing headers, a missing baggage entry, and a different test ID all produce false. Only an exact owner match produces true.

testkit/mocks/MockInstaller.kt 
if (stubs != null) {
    val ownedStubs =
        stubs.filter { stub ->
            stub.request.headers
                ?.get(BAGGAGE_HEADER)
                ?.matchesTestId(testId) == true
        }

    for (stub in ownedStubs) {
        try {
            admin.removeStub(checkNotNull(stub.id) {
                "Matching mapping has no ID"
            })
            removedMappings++
        } catch (failure: CancellationException) {
            throw failure
        } catch (failure: Exception) {
            recordFailure(
                target = target,
                admin = admin,
                operation = CleanupOperation.DELETE_MAPPING,
                mappingId = stub.id,
                cause = failure,
            )
        }
    }
}
if (stubs != null) {
    for (StubMapping stub : stubs) {
        if (!matchesTestId(stub, testId)) continue;
        try {
            admin.removeStub(Objects.requireNonNull(
                stub.id(), "Matching mapping has no ID"));
            removedMappings++;
        } catch (CancellationException failure) {
            throw failure;
        } catch (Exception failure) {
            recordFailure(target, admin, DELETE_MAPPING, failure, stub.id());
        }
    }
}

WireMock assigns the mapping ID during registration. Cleanup obtains it from listStubs. checkNotNull turns a missing ID into a recorded delete failure. The counter increases only after a successful delete. A failed delete does not stop later mappings or targets.

6. Remove journal events independently

Journal cleanup sits after the nullable mapping block. Therefore it runs when mapping listing fails. It also runs after any individual delete failure. Its return value is the number of removed events for this target.

try {
    removedRequestEvents += admin.removeRequests(requestCriteria)
} catch (failure: CancellationException) {
    throw failure
} catch (failure: Exception) {
    recordFailure(
        target = target,
        admin = admin,
        operation = CleanupOperation.REMOVE_REQUEST_EVENTS,
        cause = failure,

try {

    throw failure;
} catch (Exception failure) {

7. Return success or throw one aggregate failure

Cleanup constructs one result after all reachable work. orThrow returns the same result when the failure list is empty. Otherwise it throws CleanupException with that result. The exception attaches each original cause as a suppressed exception.

testkit/mocks/MockInstaller.kt · framework/wiremock/Cleanup.kt 
return CleanupResult(
    testId = testId,
    removedMappings = removedMappings,
    removedRequestEvents = removedRequestEvents,
    failures = failures.toList(),
).orThrow()
CleanupResult result = new CleanupResult(
    testId, removedMappings, removedRequestEvents, List.copyOf(failures));
if (!result.completed()) throw new CleanupException(result);
return result;

Ordinary failures become CleanupFailure values. Cleanup continues after them. The final CleanupException contains the complete result and suppressed causes. A cancellation is different. It stops cleanup immediately and stays a cancellation.

Exact means literal. A test ID such as A.+[1] does not own Axx1, A.+[1]-suffix, or another near match.

5Kotlin, feature by feature

These features carry the lifecycle contract. Each feature has a Java anchor.

fun T.f() copy

static helper plus record withers or builders

scopedTo is an extension function on PlannedStub. It does not change the class. Kotlin compiles it as a static function. The call reads like an instance method.

The models are data classes. Their copy functions keep all fields except named changes. Three nested copies replace the mappings, request, and headers. The original stub stays unchanged. Every mapping receives the new matcher. 

internal fun PlannedStub.scopedTo(testId: String): PlannedStub =
    copy(mappings = mappings.map { mapping ->
        mapping.copy(request = mapping.request.copy(
            headers = mapping.request.headers.orEmpty() +
                (BAGGAGE_HEADER to testIdHeaderMatcher(testId)),
        ))
    })
static PlannedStub scopedTo(PlannedStub stub, String testId) {
    List<StubMapping> mappings = stub.mappings().stream()
        .map(mapping -> mapping.withRequest(
            mapping.request().withHeaders(overlayTestId(mapping, testId))))
        .toList();
    return stub.withMappings(mappings); // hand-written wither
}
What breaks without the central scope operation?

Each builder must add the header. One builder can omit it. The mapping can serve traffic, but cleanup cannot find it. One post-builder operation prevents this state.

T? ?. orEmpty

@Nullable plus null checks and an empty default

StubInstallEvidenceSink? can be null. Provisioning uses no evidence sink. evidenceSink?.recordInstalledStub(...) calls the method only when the sink exists.

Mapping headers can also be null. orEmpty() changes a null map to an empty map. The + operation creates a new map. The new entry replaces an old entry with the same key.

operator get entries

get method with bracket syntax; Enum.values()

WireMockInstances defines operator fun get. This permits wiremock[target]. Java calls the same idea as wiremock.get(target).

WireMockTarget.entries is the typed list of all enum constants. Cleanup uses it as the single target inventory. A new enum constant becomes part of cleanup automatically. 

for (target in WireMockTarget.entries) {
    val admin = wiremock[target]
    // clean this target
}
for (WireMockTarget target : WireMockTarget.values()) {
    WireMockAdmin admin = wiremock.get(target);
    // clean this target
}

suspend withContext

async I/O with direct control flow; a protected cleanup section

WireMock Admin operations perform HTTP I/O. A suspend function can pause without blocking its thread. Its code still reads from top to bottom.

removeFor enters NonCancellable before cleanup starts. A scenario cancellation cannot prevent recovery from starting. The inner catches still rethrow a CancellationException if an Admin call reports one. 

suspend fun removeFor(testId: String): CleanupResult =
    withContext(NonCancellable) {
        removeScopedStateFor(testId)
    }
// Java has no direct NonCancellable equivalent.
// A lifecycle owner must run cleanup in a scope that outlives cancellation.
CleanupResult removeFor(String testId) {
    return cleanupExecutor.run(() -> removeScopedStateFor(testId));
}

local fun mutableListOf

private helper near one method plus ArrayList

recordFailure exists only inside removeScopedStateFor. It can use the local failures list without a field or extra parameter. This keeps aggregation state inside one cleanup attempt.

mutableListOf creates a mutable list. The += operation appends one failure. The method sends failures.toList() to the result. Callers receive a read-only list view.

catch (x: Type) ?.

ordered catch clauses and guarded member access

Kotlin catch clauses work like Java catch clauses. Order matters. The code catches CancellationException first and rethrows it. It then catches ordinary Exception values and records them.

A failed list operation sets stubs to null. The if (stubs != null) check smart-casts it to a non-null list inside the block. Journal cleanup stays outside that block. It still runs after a list failure.

Why not use runCatching?

runCatching catches Throwable. It can turn cancellation into an ordinary result. Explicit catch clauses show that cancellation must propagate.
